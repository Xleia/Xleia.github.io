# SpringBoot3-基础特性

## 1、SpringApplication

### 1.1 自定义 banner

```javascript
#设置banner
spring.banner.location=classpath:banner.txt
#关闭banner
spring.main.banner-mode=off
```

### 1.2 自定义 SpringApplication

```java
@SpringBootApplication
public class Boot306FeatureApplication {

    public static void main(String[] args) {
        // 1、SpringApplication：Boot应用的核心API入口
//        SpringApplication.run(Boot306FeatureApplication.class, args);

        // 1.自定义SpringApplication的底层设置
        SpringApplication springApplication = new SpringApplication(Boot306FeatureApplication.class);

        // 调整SpringApplication的参数
//        springApplication.setDefaultProperties();
        // 这个程序化配置优先级低于配置文件配置
        springApplication.setBannerMode(Banner.Mode.CONSOLE);

        // 2.SpringApplication 运行
        springApplication.run(args);
    }

}
```

### 1.3 FluentBuilder API

```java
        // 2、Build方式构建SpringApplication：通过FluentAPI进行设置
        new SpringApplicationBuilder()
                .main(Boot306FeatureApplication.class)
                .sources(Boot306FeatureApplication.class)
                .bannerMode(Banner.Mode.CONSOLE)
//                .listeners(null)
//                .environment(null)
                .run(args);
```

## 2、Profiles

做环境隔离的：快速切换开发、测试、生产环境

主要步骤：

1、使用@Profile标识组件在什么样的环境生效

2、激活当前项目是什么环境（默认是default环境）

### 2.1 使用

#### 2.1.1 指定环境

Spring Profiles提供了<b>配置隔离</b>的方式

任何<code>@Component,@Configuration或@ConfigurationProperties</code>可以使用<code>@Profile</code>标记，用来指定何时被加载【只要是容器中的组件都可以被<code>@Profile</code>标记】

#### 2.1.2 环境激活

方式一：配置激活环境

```javascript
# 配置环境
spring.profiles.active=default,dev
```

方式二：命令行激活

```shell
java -jar xxx.jar --spring.profiles.active=xxx
```

#### 2.1.3 环境包含

可以添加额外的生效文件，而不是激活替换。比如：

```javascript
spring.profiles.include[0]=common
spring.profiles.include[1]=local
```

- 生效的环境 = 激活的环境/默认环境 + 包含的环境
- 项目中一般这样写
- 基础配置（比如：<code>Mybatis、log</code>）写道包含环境中
- 需要动态切换变化的配置（比如：<code>db、redis</code>）写道激活的环境中

### 2.2 Profile分组

还可以给环境进行分组，将环境添加到组里面，然后直接激活那一组就可以了

```javascript
spring.profiles.active=hhh
spring.profiles.group.hhh=dev,test
```

### 2.3 Profile配置文件

- <code>applicaiton-{profile}.properties</code>可以作为指定环境的配置文件
- 激活这个环境，配置文件就会生效，最终生效的所有配置是
- <code>application.properties</code>：主配置文件
- <code>applicaiton-{profile}.properties</code>：指定环境的配置文件

注意：<code>spring.profiles.active</code>和<code>spring.profiles.default</code>只能用到无 profile 的文件中，如果在<code>application-dev.yaml</code>中编写是<b>无效的</b>

## 3、外部化配置

场景：线上应用如何快速修改配置，并应用最新配置

- SpringBoot使用 <b>配置优先级 + 外部配置</b> 简化配置更新、简化运维
- 只需要给 jar 应用所在的文件放一个 [application.properties](http://application.properties) 最新配置文件，重启项目就能自动应用最新配置

### 3.1 配置优先级

SpringBoot允许将配置外部化，可以使用各种<b>外部化配置源</b>，包括：<code>Java properties文件、yaml文件、环境变量和命令行参数</code>。可以通过<code>@Value</code>获取值，也可以用<code>@ConfigurationProperties</code>将所有属性绑定到<code>Java object</code>中

<b>SpringBoot配置加载优先级：</b>（由低到高）

- <i>默认属性（通过SpringApplication.setDefaultProperties指定的）</i>
- <code>PropertySource</code>指定加载的配置（需要写在<code>@Configuration</code>类上才有效）
- <i>配置文件（</i><i><code>application.properties/yaml等</code></i><i>）</i>
- RandomValuePropertySource支持的random.\*配置〈如:@value(“\$[random.int](http://random.int)”))
- OS环境变量
- Java系统属性（<code>System.getProperties()</code>）
- JNDI属性(来自<code>java:comp/env</code>)
- <code>ServletContext </code>初始化参数
- <code>ServletConfig </code>初始化参数
- <code>SPRING_APPLICATION_JSON</code>属性(内置在环境变量或系统属性中的JSON\}
- <i>命令行参数</i>
- 测试属性。(<code>@SpringBootTest</code>进行测试时指定的属性)
- 测试类<code>@TestPropertySource</code>注解
- Devtools 设置的全局属性。(<code>SHOME/.config/spring-boot</code>)

<b>配置文件优先级</b>：（由低到高）

- <b>jar包内</b>的<code>application.properties/yml</code>
- <b>jar包内</b>的<code>application-{profile}.properties/yml</code>
- <b>jar包外</b>的<code>application.properties/yml</code>
- <b>jar包外</b>的<code>application-{profile}.properties/yml</code>

如果<code>.properties</code>、<code>.yml</code>、<code>.yaml</code>文件同时存在，则

properties > yml > yaml

### 3.2 外部配置

在<code>/config</code>包下的配置文件优先级高于路径<code>/</code>下的配置文件

### 3.3 导入配置

使用<code>spring.config.import</code>导入额外配置

### 3.4 属性占位符

配置文件中可以使用<code>${key的名称}</code>形式取出配置的值

例如：

```javascript
app.name=MyAPP
# 如果有app.name，则取它的值，否则取“默认值”
app.desc=${app.name:默认值}
```

## 4、单元测试-JUnit5整合

#### 4.1 整合

首先导入坐标（创建spring boot项目默认自带此坐标）

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

#### 4.2 测试

<b>测试注解</b>

- <code>@Test :</code>表示方法是测试方法。但是与JUnit4的@Test不同，他的职责非常单一不能声明任何属性，拓展的测试将会由Jupiter提供额外测试
- <code>@ParameterizedTest :</code>表示方法是参数化测试，下方会有详细介绍
- <code>@RepeatedTest :</code>表示方法可重复执行，下方会有详细介绍
- <code>@DisplayName :</code>为测试类或者测试方法设置展示名称
- <code>@BeforeEach :</code>表示在每个单元测试之前执行
- <code>@AfterEach :</code>表示在每个单元测试之后执行
- <code>@BeforeAll :</code>表示在所有单元测试之前执行
- <code>@AfterAll :</code>表示在所有单元测试之后执行
- <code>@Tag :</code>表示单元测试类别，类似于JUnit4中的@Categories
- <code>@Disabled :</code>表示测试类或测试方法不执行，类似于JUnit4中的@Ignore
- <code>@Timeout :</code>表示测试方法运行如果超过了指定时间将会返回错误
- <code>@ExtendWwith :</code>为测试类或测试方法提供扩展类引用
